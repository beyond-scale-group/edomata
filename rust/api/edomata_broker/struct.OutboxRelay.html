Struct OutboxRelay

pub struct OutboxRelay<N> { /* private fields */ }
Expand description

Publishes unpublished outbox items to a Publisher and marks them as sent only after the broker acknowledged them: the OutboxConsumer of edomata-backend wired to a broker.

The relay passes over the outbox once when started, then whenever one of its wake-up streams yields (the backend’s in-process outbox signal, a PostgreSQL LISTEN stream from crate::postgres::listen, …) and at least every RelayConfig::poll_interval. Items are published in sequence-number order, in batches of RelayConfig::batch_size; transient failures are retried with exponential backoff and nothing is marked as sent until the batch succeeded, so delivery is at-least-once.

Several replicas can run the same relay with run_as_leader: a PostgreSQL advisory lock makes sure only one publishes at a time.

If the process stops after the broker acknowledged a batch but before the items were marked, the next pass publishes them again with the same BrokerMessage::id: consumers deduplicate on it.

use std::sync::Arc;

use edomata_backend::eventsourcing::Backend;
use edomata_backend::inmemory::InMemoryDriver;
use edomata_broker::{MessageEncoder, OutboxRelay, RecordingPublisher, RelayConfig, RetryPolicy};
use edomata_core::*;

struct Counter;
impl DomainModel for Counter {
    type State = i32; type Event = i32; type Rejection = String;
    fn initial(&self) -> i32 { 0 }
    fn transition(&self, e: &i32, s: i32) -> Result<i32, NonEmpty<String>> { Ok(s + e) }
}

let dsl = Counter.dsl::<i32, String>();
let backend = Backend::builder(Counter, dsl)
    .driver(InMemoryDriver::new())
    .build_default()
    .await?;
let service = backend.compile(dsl.router(move |n: i32| dsl.accept(n).publish([n.to_string()])));
for (id, n) in [("c1", 1), ("c2", 2)] {
    assert!(service(CommandMessage::new(id, chrono::Utc::now(), "counter-1", n)).await?.is_ok());
}

let publisher = Arc::new(RecordingPublisher::new());
let relay = OutboxRelay::new(
    Arc::clone(backend.outbox()),
    Arc::clone(&publisher) as _,
    MessageEncoder::serde(),
    // Give up at the first failure, to show it in this example.
    RelayConfig::new("counters").with_retry(RetryPolicy { max_retries: Some(0), ..RetryPolicy::default() }),
);

// The broker is down: the error is reported and nothing is marked...
publisher.fail_next(1);
assert!(relay.relay_once().await.is_err());

// ...and the next pass publishes both items, in sequence order.
assert_eq!(relay.relay_once().await?, 2);
let payloads: Vec<String> = publisher.messages().iter().map(|m| m.payload_text()).collect();
assert_eq!(payloads, [r#""1""#, r#""2""#]);

pub async fn relay_once(&self) -> Result<usize, RelayError>

One pass: publishes and marks every pending item, batch by batch. Returns the number of items published. Does not take the leader lock and ignores the wake-up streams.

§Errors
  • RelayError::Backend when reading the outbox or marking items fails;
  • RelayError::Encode when a payload cannot be encoded;
  • RelayError::Publish on a permanent publish failure, or once the RetryPolicy budget is exhausted.

Batches published before the error stay marked; the failed batch and the ones after it stay pending.

Source

pub async fn run(&self, cancel: CancellationToken) -> Result<(), RelayError>

Runs the relay until cancel fires: a pass now, then one after every wake-up and at least every RelayConfig::poll_interval. Returns Ok(()) when cancelled.

§Errors

The first error of a pass (see relay_once) stops the relay and is returned; RelayError::Cancelled when cancel fires while a batch waits to be retried. Restart the relay (with a supervisor or a retry loop) to resume from the unmarked items.

Source

pub async fn run_as_leader( &self, lock: LeaderLock, cancel: CancellationToken, ) -> Result<(), RelayError>

Runs the relay while holding the leader lock of the source: a stand-by replica keeps trying to acquire it every RelayConfig::leader_retry_interval; when the lock is lost (the database connection dropped) the relay stops publishing and goes back to standing by. Returns Ok(()) when cancel fires.

Use the same LeaderLock key for every replica of one relay, for example LeaderLock::new(pool, &config.source). A new leader resumes from the unmarked items, so a batch in flight when the lock was lost can be delivered twice.

§Errors

RelayError::Leader when the lock cannot be queried, plus the errors of run while leading.

    // On a shutdown signal (here: after an hour), stop gracefully.
    tokio::time::sleep(std::time::Duration::from_secs(3600)).await;
    shutdown.cancel();
});
relay.run_as_leader(LeaderLock::new(pool, "accounts"), cancel).await
