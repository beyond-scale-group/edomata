PostgreSQL support for relays: leader election with advisory locks, LISTEN-based wake-ups and a checkpoint table.

Structs§

LeaderGuard
The held leader lock. Dropping it closes the connection, which releases the lock server-side; release does so explicitly.
LeaderLock
Leader election through a session-level advisory lock (pg_try_advisory_lock(hashtext('edomata-relay:{source}'))): the lock is held by a dedicated connection for as long as the LeaderGuard lives, and released when the guard is released or its connection closes.
PgCheckpointStore
A CheckpointStore in the relay_checkpoints table of a namespace (DDL: [PGSchema::relay_checkpoints]), one row per relay name.

Functions§

listen
A wake-up stream fed by LISTEN channel: yields once per NOTIFY (payloads are ignored), reconnecting after connection errors. Pair it with the drivers’ with_outbox_notify_channel / with_journal_notify_channel so that a relay in another process is woken up by the writers.
