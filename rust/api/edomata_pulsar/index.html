§Edomata Pulsar

A Publisher for edomata-broker relays backed by the [pulsar] client (Apache Pulsar, including the managed add-on of Clever Cloud):

  • one Pulsar producer per topic, created lazily and cached; a producer (or the whole connection) that fails is dropped so that the next publish recreates it;
  • the stream id is the message key, which keeps per-stream ordering (also on partitioned topics: the producer routes by key);
  • the topic is chosen by a function of the message (default: one topic per relay source, i.e. per aggregate namespace); short names are placed in the configured tenant and namespace, full persistent://<tenant>/<namespace>/<topic> URLs are used as they are;
  • the message id and metadata travel as message properties (see edomata_broker::headers).

publish returns only after the broker acknowledged every message of the batch (a send receipt each); the relay marks outbox items as sent after that, so delivery is at-least-once and consumers deduplicate on the edomata-id property.

Errors are classified for the relay: invalid topics, authentication and authorization failures, rejected topics and messages larger than the configured maximum are PublishError::Permanent; everything else (connection lost, timeouts, broker not ready…) is PublishError::Transient and retried. When unsure the error is transient.

§Where it fits

edomata-pulsar depends only on edomata-core and edomata-broker: it is one Publisher implementation for the broker-agnostic OutboxRelay and JournalRelay. Applications that do not use Pulsar don’t depend on it. It has no Scala counterpart. The [pulsar] crate is re-exported for its configuration and error types.

§Limits of a shared namespace

A Pulsar producer belongs to one topic, so the number of distinct topics your topic function produces is the number of producers this publisher keeps. Managed offerings cap them: Clever Cloud documents at most 100 topics per namespace and 100 producers per topic. Prefer with_fixed_topic or a function with a bounded range; never derive the topic from a stream id.

§Example

An outbox relay publishing to one Pulsar topic with token authentication over TLS (the connection is made at the first publish, not at build time):

use std::sync::Arc;

use edomata_backend::eventsourcing::Backend;
use edomata_broker::postgres::LeaderLock;
use edomata_broker::{CancellationToken, MessageEncoder, OutboxRelay, RelayConfig};
use edomata_core::*;
use edomata_pulsar::PulsarPublisher;
use edomata_sqlx::SqlxDriver;

struct Counter;
impl DomainModel for Counter {
    type State = i32; type Event = i32; type Rejection = String;
    fn initial(&self) -> i32 { 0 }
    fn transition(&self, e: &i32, s: i32) -> Result<i32, NonEmpty<String>> { Ok(s + e) }
}

let backend = Backend::builder(Counter, Counter.dsl::<i32, String>())
    .driver(SqlxDriver::for_namespace("counters", pool.clone()).await?)
    .build_default()
    .await?;

let publisher = PulsarPublisher::builder("pulsar+ssl://broker.example.com:6651")
    .with_token("eyJ...")
    .with_namespace("my-tenant", "my-namespace")
    .with_fixed_topic("counters-notifications")
    .build()?;

let relay = OutboxRelay::new(
    Arc::clone(backend.outbox()),
    Arc::new(publisher),
    MessageEncoder::<String>::serde(),
    RelayConfig::new("counters"),
)
.wake_on(backend.updates().outbox());

relay
    .run_as_leader(LeaderLock::new(pool, "counters"), CancellationToken::new())
    .await?;

§Clever Cloud

The Pulsar add-on injects ADDON_PULSAR_BINARY_URL, ADDON_PULSAR_TOKEN, ADDON_PULSAR_TENANT and ADDON_PULSAR_NAMESPACE; PulsarPublisherBuilder::from_clever_env reads them.

§Feature flags

This crate has no Cargo feature flags of its own. The pulsar client is built with TLS through rustls (no system OpenSSL), without OAuth2 authentication and without message compression; building it needs the protoc protobuf compiler.

Functions§

default_topic
The default topic: the relay source with every character outside [A-Za-z0-9._-] replaced by - (a safe subset of Pulsar’s topic name alphabet), that is one topic per relay source, see sanitize_topic.
resolve_topic
Resolves a topic to a full Pulsar topic name.
sanitize_topic
Makes a string a valid Pulsar topic name (the part after the namespace): every character outside [A-Za-z0-9._-] becomes - (a safe subset of the alphabet Pulsar accepts), and an empty name becomes "edomata".
