Struct RlsGateway 

Source 
pub struct RlsGateway<T = TenantId> { /* private fields */ }
Expand description

The single entry point to the event-sourced tables of a SaaS service under Row-Level Security.

Every transaction that touches them starts in begin, which, inside the transaction:

  1. switches to the role of the access (SET LOCAL ROLE; PostgreSQL refuses it unless the connection’s login is a member of that role, which is what keeps the system and inspection modes out of reach of a login that was not granted them), then
  2. sets the tenant with set_config(setting, value, true): transaction-local, so it ends with the transaction and a pooled connection never carries a tenant into its next use. A missing or empty tenant matches no row.

Nothing outside this type sets the role or the tenant, and nothing in the policies trusts a setting the application can change freely: the tenant setting only selects rows within the tenant role.

let policy: RlsAccessPolicy<TenantId> = RlsAccessPolicy::with_prefix("shop")?;
let gateway = RlsGateway::new(pool, policy.clone());

// Raw SQL, as tenant "acme": the transaction is committed on `Ok`.
let access = policy.tenant_access(&TenantId::new("acme"))?;
let visible: i64 = gateway
    .run(&access, |conn| {
        Box::pin(async move {
            sqlx::query_scalar("select count(*) from shop_journal")
                .fetch_one(conn)
                .await
                .map_err(edomata_backend::BackendError::unknown)
        })
    })
    .await?;

// A backend: every transaction of its driver runs as the tenant role,
// for the access of the surrounding `with_access`.
let driver = gateway.driver(PGNaming::prefixed_str("shop")?).await?;

pub async fn begin( &self, access: &Access, ) -> Result<Transaction<'static, Postgres>, BackendError>

Opens a transaction, switches to the role of access and injects the tenant (see the type documentation). The transaction rolls back when dropped; commit it to keep its writes.

§Errors

BackendError::PersistenceError when access does not come from this gateway’s policy; BackendError::UnknownError when PostgreSQL refuses (for example, the login is not a member of the role).

where F: for<'c> FnOnce(&'c mut PgConnection) -> BoxFuture<'c, Result<V, BackendError>>,

Runs f in a transaction opened by begin and closes it: committed when f returns Ok, rolled back otherwise.

§Errors

The errors of begin, of f, and of the commit.

Source

pub async fn with_access<Fut: Future>( &self, access: &Access, future: Fut, ) -> Fut::Output

Runs future with access as the ambient access of every driver built by driver (and of tx_scope): the web tier calls it once per request, with the authenticated tenant, around service.handle(..). The access is a task-local value: it does not follow tokio::spawn, and a driver used outside any with_access fails instead of running unscoped.

pub fn fixed_scope(&self, access: Access) -> Arc<dyn TxScope> ⓘ

A TxScope that always uses access, whatever the ambient access: for the background writes of a persisted snapshot store (SqlxDriver::with_snapshot_write_scope), which have no caller. Using the system mode there needs the login to be a member of the system role.

Source

pub async fn driver(&self, naming: PGNaming) -> Result<SqlxDriver, BackendError>

An event-sourcing driver whose every transaction (journal, outbox, commands, snapshots; reads included) goes through begin for the ambient access of with_access. No DDL is run: the tables belong to the migration role (SaaSPGSchema::eventsourcing_rls).

§Errors

Never in practice (no DDL is executed); the signature follows SqlxDriver::new_with.
