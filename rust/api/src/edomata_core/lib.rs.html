1//! # Edomata core
2//!
3//! Core abstractions of [Edomata](https://github.com/beyond-scale-group/edomata),
4//! a lightweight library for building event-driven automata: event-sourced
5//! aggregates ([`Edomaton`]) and CQRS state machines ([`Stomaton`]).
6//!
7//! This crate is pure and runtime-agnostic: it has no dependency on any
8//! async runtime and compiles to `wasm32-unknown-unknown`. Programs are
9//! `Send` futures, so they can be driven by any executor (Tokio in the
10//! PostgreSQL backends).
11//!
12//! | Type | Purpose |
13//! |------|---------|
14//! | [`Decision`] | State machine with `Accepted` / `Rejected` / `InDecisive` outcomes |
15//! | [`ResponseD`] | A decision combined with notifications |
16//! | [`ResponseE`] | A `Result` combined with notifications |
17//! | [`Edomaton`] | Event-driven automaton (full event sourcing) |
18//! | [`Stomaton`] | State-only automaton (CQRS without event sourcing) |
19//! | [`DecisionT`] | Asynchronous decision |
20//! | [`Action`] | Asynchronous response |
21//! | [`DomainModel`] | Initial state and event transitions of an aggregate |
22//! | [`DomainCompiler`] | Folds a program's decision into the model |
23//!
24//! ```
25//! use edomata_core::*;
26//!
27//! // A counter that only accepts positive increments.
28//! struct Counter;
29//!
30//! impl DomainModel for Counter {
31//!     type State = i32;
32//!     type Event = i32;
33//!     type Rejection = String;
34//!
35//!     fn initial(&self) -> i32 { 0 }
36//!
37//!     fn transition(&self, event: &i32, state: i32) -> Result<i32, NonEmpty<String>> {
38//!         if *event > 0 { Ok(state + event) } else { Err(NonEmpty::new("negative".into())) }
39//!     }
40//! }
41//!
42//! let dsl = Counter.dsl::<i32, String>();
43//! let app = dsl.router(move |by| {
44//!     if by == 0 { dsl.reject("zero".to_string()) } else { dsl.accept(by).publish(["changed".to_string()]) }
45//! });
46//!
47//! let ctx = CommandMessage::new("cmd-1", chrono::DateTime::UNIX_EPOCH, "counter-1", 5).build_context(10);
48//! let outcome = futures::executor::block_on(app.execute(&Counter, ctx));
49//! assert_eq!(outcome, EdomatonResult::Accepted {
50//!     new_state: 15,
51//!     events: nonempty![5],
52//!     notifications: vec!["changed".to_string()],
53//! });
54//! ```
55//!
56//! ## Where it fits
57//!
58//! `edomata-core` is the pure base of the workspace: it depends on no other
59//! Edomata crate, and every other crate builds on it, directly or (for
60//! `edomata-serde`, through `edomata-backend`) indirectly, except
61//! `edomata-postgres`, which is independent of it.
62//!
63//! - `edomata-backend` runs [`Edomaton`] and [`Stomaton`] programs against a
64//!   storage (journal, snapshots, outbox, optimistic concurrency, retries)
65//!   and ships an in-memory driver;
66//! - `edomata-postgres`, `edomata-serde` and `edomata-sqlx` provide the
67//!   PostgreSQL naming and DDL, the payload codecs and the sqlx driver;
68//! - `edomata-testkit` has assertion helpers for unit-testing programs;
69//! - `edomata-saas` / `edomata-saas-sqlx` add multi-tenancy,
70//!   `edomata-simple` a closure-based facade, and `edomata-broker`,
71//!   `edomata-kafka` and `edomata-rabbitmq` distribute notifications.
72//!
73//! Domain code usually only needs this crate: define a [`DomainModel`] (or a
74//! [`CqrsModel`]), write programs with its [`DomainDsl`] (or
75//! [`CqrsDomainDsl`]), and unit-test them with [`Edomaton::execute`].
76//!
77//! ## Feature flags
78//!
79//! | Feature | Default | Effect |
80//! |---------|---------|--------|
81//! | `serde` | no | Derives `serde::Serialize` / `serde::Deserialize` for [`CommandMessage`], [`MessageMetadata`] and [`NonEmpty`] (and enables `chrono/serde`). Deserializing an empty sequence into a [`NonEmpty`] fails with [`EmptyError`]. |

118/// A boxed, `Send` future, the shape of every effect in Edomata programs.
119///
120/// [`Edomaton::run`], [`Stomaton::run`], [`Action::run`] and
121/// [`DecisionT::run`] all return this type.
122pub type BoxFuture<'a, T> = Pin<Box<dyn Future<Output = T> + Send + 'a>>;
123
124/// A result carrying one or more rejections, the counterpart of Cats'
125/// `EitherNec`.
126pub type ResultNec<T, R> = Result<T, NonEmpty<R>>;
127
128/// The type of a domain service: handles a command and returns unit or the
129/// rejection reasons.
130///
131/// Backends compile an [`Edomaton`] (or a [`Stomaton`]) into a function of
132/// this shape, which hides storage, concurrency and retries from callers.
133pub type DomainService<'a, C, R> = dyn Fn(C) -> BoxFuture<'a, ResultNec<(), R>> + Send + Sync + 'a;
